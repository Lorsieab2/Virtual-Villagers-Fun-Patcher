# Expanded-256 is already unreachable, and stays that way

The expanded-256 population modes for VV3, VV4 and VV5 are dead. They crash and
break the game and must never be offered to a player.

## Current state: already unreachable

`data/builds.json` declares exactly three patch modes:

```
stock
collection_progression
immediate_fixed
```

`experimental_expanded_256` and `experimental_expanded_256_progression` are
**not among them**, so no player can select either one. `README.md` and
`How to Use.txt` both already state the modes are removed from the patcher.

`tests/test_expanded_256_is_not_selectable.py` locks this in: it fails if an
expanded mode is ever declared as a patch mode, offered as a per-game variant,
or added to the declared set. It is mutation-tested — re-declaring
`experimental_expanded_256` is caught.

That test also asserts `EXPANDED_PATCH_MODES` still exists, so that if the
scaffolding is genuinely removed one day the file cannot start passing
vacuously; delete the file at that point instead.

## Why the internal scaffolding is still present

The constants and guard scaffolding remain because the two live modes,
`collection_progression` and `immediate_fixed`, share code paths with them.
Removing the scaffolding outright is not safe today — that is the same blocker
recorded when the 55 stale VV3/VV4/VV5 expanded build artifacts were deleted.

## Why the VV5 manifest prose was not churned

`data/vv5_origins_feature.json` still describes an expanded-256 gate in its
`doubler_purchase_status`, and that text reaches the generated transparency
log. Rewriting it to match VV1-VV4's wording is a one-line change to
`scripts/build_vv5_origins_feature.py`, but regenerating the manifest moves a
chain of pinned source-text hashes:

1. `data/vv5_origins_feature.json` text hash
2. `VV5_TASK9_ACTIVE_SOURCE_TEXT_SHA256` in `src/vv_fun_patcher.py`
3. `base_source_text_sha256` in the VV5 Task9 manifest and candidate map
4. the Task9 builder's own pinned source-text hash, which changes again as soon
   as step 3 edits that builder
5. the Task9 manifest's `source_bindings`, regenerated by a builder that
   re-checks step 1 and refuses on drift

Each layer guards real provenance, so each has to be re-pinned deliberately and
in order. That is worth doing as its own focused change with the full suite as
the gate; it is not worth folding into unrelated work, where a subtly wrong
re-pin would be easy to miss.

The wording is inaccurate but harmless: it describes a restriction on a mode
that cannot be chosen. Nothing a player can select behaves differently because
of it.
