# VV2–VV5 collectibles and Expanded-256 disassembly plan

This is an additive, disabled evidence plan. It does not add native bytes, catalog entries, routes, resources, runtime behavior, or publication authority. All four games remain `STOP`, `native_output=false`, and hidden from enablement.

The plan has ten ordered workstreams. Each must be answered from a complete no-follow game-folder inventory and an automated, unedited IDA/Ghidra export:

1. selected-world resolver;
2. collectible roster/detail tables;
3. eligibility predicates and their exact order;
4. capacity, stored-index width, sentinel, and 255/256–259 boundaries;
5. native writers/setters and partial-effect boundaries;
6. notification, statistics, trophy/collection, and queue effects;
7. confirmation, IDOK/cancel, identity/funds reacquisition, deduction, and postverify;
8. save serializer/loader/header/body/rotation;
9. Expanded-256 consumers across all ten path categories;
10. reload, offline catch-up, manager/pool identity, Origins interaction, and runtime/player receipts.

Every unresolved function name, VA, raw offset, preimage, ABI, register contract, stack cleanup, xref, and return/failure contract is intentionally absent from the query map. A candidate edit offset is navigation metadata only and never qualifies as native evidence.

## Required evidence package

For each game and each workstream, the future export must bind exact function ranges, instruction bytes and file offsets, register/stack/return contracts, every caller/callee/xref, source artifact and folder inventory identity, and any runtime/player receipt. Expanded-256 must additionally prove every required category, exact logical/physical bounds, record 255 acceptance, indices 256–259 unreachable and non-saveable, serializer/deserializer bounds, terminator/tail behavior, failed-load nonmutation, rotation, catch-up order, and manager/pool identity after reload.

Until that package exists, no collectible or Expanded-256 native route may be enabled or published.
