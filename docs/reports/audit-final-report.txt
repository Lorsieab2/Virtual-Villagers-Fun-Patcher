2. EACH DEFECT: CAUSE, FIX AND EVIDENCE
==================================================================

D1. VV3 "Pointing Out a Rare Collectible Always Works" corrupted memory   PR #470
  Cause: after a rejected pick, the retry jumped back to the loop start (0x42DC85 ->
  0x42DB70), but by then three registers the loop depends on held other values
  (EDI, ESI, EBP). Each reroll therefore wrote the collectible outside the tracker's
  two slots, into neighbouring game data.
  Emulated with main's patch: one refused pick produced 12 stray writes (0x58F890...)
  and placed nothing. When every pick is refused, it ran until it wrote to unmapped
  memory, which in the game means a crash or wider corruption. Shipped since v1.34.14.
  Fix: the stock routine is now completely untouched. Its only call site calls a small
  wrapper that runs the stock routine and stops once a collectible is placed, up to 20
  tries. The description now says so honestly.
  Test: the real routine is executed and every memory write is recorded. There are no
  stray writes, a refused pick is rerolled, and the retries are capped at 20. Against the
  old patch this test fails.

D2. VV1 parentage altered game state (Golden Child marker)                 PR #475
  Cause: the capture overwrote an argument believed to be unused. The game stores it in
  the mother's +0x394, which it later compares with 0xC7, the Golden Child marker. The
  field held a pointer instead; at one pairing site it held the mother's own slot index.
  In the 256-population modes, a mother in slot 199 could therefore produce a spurious
  Golden Child.
  Fix: no conception call is patched any more, so the game's arguments are exactly
  stock. The father is read from the caller's own stack frame instead.
  Test: 24 conception paths x 4 builds, each compared with a stock run. +0x394, all
  villager records and the registers match stock, and the log gets the real father.

D3. VV4 statistics grave seed could make a save fail to load               PR #472
  Cause: released builds wrote +0x37 = 1 on graves with a certain stock flag. That
  byte is the top byte of the field at +0x34, so the stock memorial loader rejects the
  grave, and with it the whole save.
  Your saves: all 36 VV4 saves were scanned read-only. None is affected today. Applying
  the seed to a copy in memory makes 20 of them fail to load in stock.
  Fix: a load-time repair in every mode. It fires only on exactly that seed pattern and
  restores the stock value. Valid graves are untouched and other invalid graves are
  still rejected, as in stock. (#467 removes the seeding itself.)
  Test: the real loader is emulated; 8 deliberately broken variants are all caught.

D4. VV3 Nature honey refill: the hive never refilled                       PR #468
  Cause: the amount of honey to add was divided by 2048 twice, so 0 was added while the
  refill timer still reset. Shipped since v1.34.14.
  Emulated, honey starting at 100:
    stock game: 102 after 1 h, 148 after 24 h
    main:       100 after 1 h, 100 after 24 h
    fixed:      102 after 1 h, 148 after 24 h (Nature 0);
