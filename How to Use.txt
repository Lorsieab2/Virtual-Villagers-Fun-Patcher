VIRTUAL VILLAGERS FUN PATCHER

SUPPORTED GAME SOURCE

This patcher only supports the games downloaded from the official Last Day of
Work (LDW) website (ldw.com), where all five PC games are free -- so there is
no reason to get them from anywhere else. Every patch is pinned to the exact
bytes of those free LDW builds.

Other releases, such as the Steam version, are not tested and may have
different bytes. The patcher checks each executable's SHA-256 against the
exact supported build and refuses anything that does not match, rather than
risk patching an unverified executable. If your game is rejected, re-download
it from ldw.com.

PHYSICAL POPULATION LIMITS

A New Home and The Lost Children have 256 stock villager records.
The Secret City, The Tree of Life, and New Believers have 150 stock records.
The old Expanded-256 population modes have been removed from the patcher; for
those three games, the optional "256 Villagers (Experimental)" patch gives 256
slots instead (see the 256 VILLAGERS (EXPERIMENTAL) section below).

1. Double-click "Launch Virtual Villagers Fun Patcher.bat".

   - No Population Increase:

     physical-capacity safety still clamps allocation paths at the real record
     pool; it does not change the stock social cap.
   - Collection Progression Max Pop:
     Collections still raise the cap and are needed to reach the absolute
     maximum. The Secret City also retains its level-3 magic bonus.
   - Immediate Fixed Max Pop:
     The absolute maximum is available immediately. Collections no longer
     affect it, and The Secret City's magic tech no longer affects it.
3. Optional for A New Home: check "School Lessons Grant Skill",

   Grant Full Mastery to All Villagers is part of the current Origins menus; the historical standalone

   "Everyone Tries On the Robe", "Birth Control", and/or

   "Pointing Out a Rare Collectible Always Works" and/or

BACK UP SAVES

The patcher can copy your modded games' saves for you, in all five games.

1. On the One Game tab, choose the game's EXE and click "Back Up Saves".
   On the All 5 Games tab, click "Back up saves" on a game's row, or
   "Back Up Saves (All 5)..." for every game at once.
2. A window lists that game's save folders in Documents\LDW: the
   "(Game name) - Modded" folder, "- Modded 256" for a 256 Villagers build,
   and any other "- Modded..." folder there. Folders the patcher's own builds
   use are ticked; tick or untick any of them, then click "Back Up Selected".
3. Each chosen folder is copied -- your .ldw saves, the "Virtual Villagers
   Fun Patcher Logs" and "Virtual Villagers Fun Patcher Data" folders and
   everything else in it -- into a new folder inside it:
       (save folder)\Backups\Backup YYYY-MM-DD HH-MM-SS
   Every copied file is checked against the original. An earlier backup is
   never replaced, and nothing in the patcher ever reads or deletes the
   Backups folder (Start Over leaves it alone).
4. If the game is running, it is paused for the copy and then carries on by
   itself; it is never closed. These games save only when you quit them
   normally, so a backup made while a game is running holds the village as of
   its last save. If the game cannot be paused, nothing is copied and the
   window says why.
5. The result window shows how many files were copied and their size, with an
   "Open Backup Folder" link.

RESTORE SAVES

1. Quit the game from its own menu first. A restore is refused while the game
   is running, because a running game writes its village over the restored
   save when it quits. The patcher never closes the game for you.
2. Click "Restore Saves..." on the One Game tab, or "Restore saves..." on a
   game's row on the All 5 Games tab.
3. The window lists that game's backups, newest first, each with its date and
   time, which variant ("Modded", "Modded 256" ...) it came from, the village
   in each save slot, and its size.
4. Choose "The whole save folder" or "One save slot only" and the slot, then
   click "Restore...". A confirmation lists exactly which files will be
   replaced, added and removed.
   One slot restores only that slot's saves and that slot's patcher files.
   It is refused, and the window says why, when the backup and your saves
   differ in a file that belongs to no single slot (the game's shared slot 0
   save, or a patcher file that does not say which save it is for); restore
   the whole save folder instead.
5. Before anything is changed, your saves as they are now are backed up as
   "Backup (date) (before restore)", so every restore can be undone by
   restoring that backup. Each file is put in place only after its copy has
   been checked against the backup; if anything goes wrong, every file already
   changed is put back.
6. "Delete Backup..." deletes the chosen backup after asking. A restore never
   changes or deletes any backup.

RENAME TRIBE

The patcher can change a tribe's name inside its save, in all five games.

1. Quit the game first (from its own menu). A game that is running is
   refused: it saves when you quit it, which would put the old name back.
2. On the One Game tab, choose the game's EXE and click "Rename Tribe...".
   On the All 5 Games tab, click "Rename tribe..." on a game's row, or
   "Rename Tribe..." below them to pick any game.
3. Pick the game, the save folder (every "- Modded..." folder, as Back Up
   Saves lists them) and the tribe. Each save slot is listed with its
   current name.
4. Type the new name. The counter shows the game's own limit: 31 characters
   in A New Home and The Lost Children, 19 in The Secret City, The Tree of
   Life and New Believers. A New Home and The Lost Children cannot draw
   # $ % & ( ) * + ; < = > @ [ \ ] ^ _ { } | ~ in a name. A name that is too
   long or uses those characters is refused, never cut short.
5. Click "Rename". The save folder is backed up first, into
       (save folder)\Backups\Backup YYYY-MM-DD HH-MM-SS (before rename)
   Restore Saves lists that backup like any other, so a rename can be undone.
   Then the name is changed in the slot's save, its older copies and the
   slot list. Every file is checked after writing; if anything fails, every
   file is put back as it was.
6. The patcher's logs carry on for the same village. Nothing already in them
   is changed; each gets one line, "Tribe renamed from <old> to <new> on
   <date>", and new records keep going into the same logs under the new name.

CHECK LOGS AND REPAIR LOGS

"Check Logs..." shows whether every log and data file the patcher keeps for
one village agrees with its save. It only reads: nothing is changed, so the
game may be running.

1. On the One Game tab, choose the game's EXE and click "Check Logs...".
   On the All 5 Games tab, click "Check logs..." on a game's row, or
   "Check Logs..." below them to pick any game.
2. Pick the game, the save folder and the tribe, and click "Check".
3. The report lists each file with OK (agrees with the save), WRONG
   (confirmed wrong), NOTE (a difference that is not proof of an error) or
   UNCHECKED (nothing to check it against, or it could not be read), and a
   summary line at the end. The Backups folder is never read.

"Repair Logs..." does not change any log itself. It has the game check the
village again the next time you load it, and ask "Repair" or "Not now"
before it repairs anything.

1. Quit the game first (from its own menu). A game that is running is
   refused, never paused or closed.
2. Click "Repair Logs..." (One Game tab), "Repair logs..." on a game's row,
   or "Repair Logs..." below them, and pick the game, save folder and tribe.
3. The logs are checked first and the result shown. If nothing is found
   wrong you are told so, and can still go ahead.
4. Confirm. The save folder is backed up first, into
       (save folder)\Backups\Backup YYYY-MM-DD HH-MM-SS (before repair re-arm)
   which Restore Saves lists like any other backup. Then only the files that
   say "this village was already checked" are cleared for that save slot
   (the Cross-Check marker in A New Home, and the Graves Logged and Arrivals
   Recorded files in every game). No log, backup or other data is removed.
5. Load the tribe. After a few seconds on screen the patcher checks its logs
   and, if it finds something it can put right, asks before repairing.

OUTPUTS

All three modes and optional-patch combinations use:

(name of game) - Modded\
(name of game) - Modded.exe

Mode and optional-patch details are recorded in the modified EXE's adjacent
.patch-log.json file instead of being added to the EXE or save-folder name.
The one exception is 256 Villagers (Experimental): a game built with it is
named "(name of game) - Modded 256" (folder and EXE), so that its saves go to
a separate save folder (see 256 VILLAGERS (EXPERIMENTAL)).

For each game, the patcher creates one complete copy named
"(Game name) - Modded". The copied folder keeps every original file and
subfolder, including the stock EXE, and adds "(Game name) - Modded.exe" and its
verification log. Applying another population mode refreshes the same short Modded
folder in place after confirmation. If a Modded output location was selected,
these folders are created beneath that chosen parent instead of beside the
original. The copy is built in a hidden temporary folder beside it
(".<Modded folder name>.staging-<id>") and renamed into place only once it
has been verified. When a Modded folder is refreshed, the previous one is
moved aside to a hidden ".backup-<id>" folder until the new one verifies,
then deleted -- or renamed back if anything fails. Anything that cannot be
restored automatically is kept in a ".recovery-<id>" folder, never deleted.
Original folders and EXEs are never changed, renamed, replaced, or deleted. The
patcher remembers the selected population mode, output parent, single-game EXE path, and
all five folder paths. Vanilla and Modded links open their respective folders.

256 VILLAGERS (EXPERIMENTAL)

Optional for The Secret City, The Tree of Life and New Believers, and off by
default: "256 Villagers (Experimental)" gives the game 256 villager slots
(numbered 0 to 255) instead of 150. In a 256 build:
- Immediate Fixed Max Pop allows 256 at once.
- Collection Progression Max Pop starts at 221 in The Secret City (plus 0-25
  collection points and 10 from Magic level 3), 231 in The Tree of Life (plus
  0-25) and 241 in New Believers (plus 0-15), reaching 256 with everything.
- No Population Increase keeps the stock cap (125, 115, 105); only the table
  is larger.
- Twins, triplets and Island Events are guarded at 256 instead of 150.

Saves: the 256 build is named "(name of game) - Modded 256.exe" and keeps its
saves, logs and data files in its own folder,
Documents\LDW\(name of game) - Modded 256\, never in the ordinary "- Modded"
save folder. The patcher does not copy saves into it. To carry on an existing
village, copy its .ldw save files from Documents\LDW\(name of game) - Modded\
into the "- Modded 256" folder yourself. The village loads with all its
villagers; the first time the game saves it, it is written in a longer
256-slot format, and from then on it opens only in a 256 build. Keep the
ordinary "- Modded" saves as a backup.

The Secret City and The Tree of Life: the base game damages a save made with
exactly 150 villagers so that it no longer loads. With "Fix Vanilla Bugs"
ticked (it is on by default), the 256 build loads such a save with all 150
villagers; without it, that save is refused as in the base game.

This patch is experimental: it has passed the patcher's build tests and live
tests that filled villages to the last slots, but it has had far less play
than the other patches.

SAFE MULTIPLE BIRTHS

All five games normally check the cap before deciding singleton/twins/triplets.
All three public modes apply automatic physical-capacity safety at the selected
mode's real slot ceiling. No Population Increase preserves the stock cap and
progression; Collection Progression and Immediate Fixed retain their documented
cap behavior. The safety layer only clamps physical allocation:
- 3+ spaces: multiples work normally.
- 2 spaces: a rolled triplet becomes twins.
- 1 space: a rolled twin or triplet becomes a singleton.
- 0 spaces: the normal cap check blocks the birth.

Population-adding Island Events are protected in all five games too.
Repeated arrivals stop at the physical ceiling. VV4 and VV5 Abandoned
Infants is reduced below six when fewer than six physical slots remain.
Events that remove villagers are unchanged.

NO VILLAGER WITHOUT A FREE RECORD

Corpses, ghosts, Heathens and babies still owed all hold villager records.
In every mode (No Population Increase included, and the 256 builds) each
creation asks the records, and nothing is spent without one: a delivery
waits with the pregnancy kept until its whole litter fits; the room check
counts every occupied record and every baby owed; A New Home's Golden
Child puzzle fires only with a free record (the original game hid the
child past the end of the table); New Believers' Reanimate is refused
instead of crashing; the island events that add a villager are offered only
with room.

Only the five exact researched stock builds are supported. Unknown, modified,
corrupt, duplicate, or incorrectly assigned EXEs are refused.

VV2 EASIER HEALING MASTERY

When a healer or a villager who prefers Healing has no sick villager to treat,
the patch sends that villager into the game's existing plant-study work state.
That persistent state is used during normal play and time catch-up. Normal
healing, sickness, food, skill gains, and plant availability are unchanged.

VV1 REENABLE F6 CLOTHING CHANGE CHEAT

Press F6 to advance the selected active villager to the next stock outfit. Each
successful outfit change costs exactly 5,000 tech points. With fewer than
5,000 tech points, F6 does nothing and charges nothing. The cycle uses clothing
indices 0 through 19 and wraps from 19 back to 0. Nothing changes if no active
villager is selected. The patch does not change heads,
sex, age, skills, health, jobs, actions, or clothing assets. All non-F6 keys
retain their original behavior.

VV1 SCHOOL LESSONS GRANT SKILL

When an unlocked Going to school action reaches its end, the child gains 7, 8,
or 9 points in one equally random skill: Farming, Building, Research, Healing,
or Parenting. This matches the VV3 Tribal Chief lesson award. Skills remain
capped at 100. An interrupted school action that never reaches its completion
callback gives no skill.

VV1 MAGIC FRUIT OF LIFE ALTERS MORTALITY

Once the Magic Fruit puzzle is completed, its saved puzzle flag shifts every
ordinary villager's mortality curve seven displayed years later. The same stock
mortality routine runs during normal play and time catch-up. Medicine still
adds its original benefit, and the Golden Child keeps the stock exemption.

Whenever a villager finishes Enjoying magic fruit, the final action cleanup
clears sickness and restores health to 100. The fruit remains reusable. An
interrupted action does not cure the villager. The patch stores nothing in
villager names, likes, dislikes, or other record fields.

VV2 TEACHING CHILDREN GRANTS SKILL

When an attending child's full stock Teaching Children lesson queue reaches
its end, that child gains 7, 8, or 9 points in one equally random skill:
Farming, Building, Research, Healing, or Parenting. This matches the VV3
Tribal Chief lesson award. Skills remain capped at 100. An interrupted lesson
that never reaches its completion callback gives no skill. The patch does not
change who teaches, who attends, or how often lessons happen.

VV2 HOSPITAL RECOVERY HEALS

When a villager completes Recovering at the hospital, that villager gains
exactly 1 health point, capped at 100. Stock VV2's hospital action does not
change health. The point is awarded by the final completion callback, so an
interrupted recovery gives no health.

VV2 BIRTH CONTROL

The two writer-reaching opcode-12 candidate scans used by ordinary
autonomous/catch-up pairing and stew recipe 15 reject a candidate whose
internal age is 1000 or greater. The two exact guarded blocks are one optional
feature and are never applied separately. The stock manual carrier/female-only

VV2 GONG OF WONDER COCONUTS FIX

The Gong's coconut outcome adds 30 to the coconut trees instead of replacing
their current amount with 30. Both stock outcome paths are corrected. Other

VV3 EVERYONE TRIES ON THE ROBE

Drop one active, living, non-nursing villager on the robe. If the original
callback puts that villager into either the stock failed-fit Trying on the robe
action or the successful Tribal Chief action, every other active, living,
non-nursing villager is sent to the robe area with the stock failed-fit Trying

The dropped villager keeps the complete normal result and remains the only
villager who can become Tribal Chief. Followers receive the native status,
walk, gestures, and temporary try-on appearance, but never the successful fit,
persistent Chief clothing, or Chief state. Dead, inactive, and nursing
villagers are skipped. Fanout requires the original callback to report a
handled drop and leave the initiator in robe action 120 or 121.

This optional checkbox starts unchecked and supports the two
population-increase modes. Static install, composition, and uninstall checks
pass; player runtime confirmation is still pending. The broadcast feature
itself never reads or writes candidate fields +0xE80 or +0xE88. If the fields
are still zero
before automatic assignment, or no eligible candidate exists, the game's
native failed-fit action 121 is broadcast without granting Chief state.

VV3 NATURE LEVEL 1 ACTUALLY REPLENISHES FOOD SOURCES FASTER

At Nature level 1 or higher, fruit trees become refill-eligible after 2 hours
15 minutes instead of 3 hours, and honey becomes refill-eligible after 45
minutes instead of 1 hour. Fruit trees retain their stock Nature quantity
bonus: approximately 126 instead of 111 fruit for the same stock refill group,
now delivered after the shorter interval. Honey receives the same 42/37

level 0 keeps stock timing and amounts. The 3,000-unit honey cap is unchanged.

VV3 NATURE LEVEL 3 ACTUALLY ALTERS MORTALITY

At Nature level 3, every ordinary villager's complete mortality curve shifts
seven displayed years later. Medicine's stock longevity threshold is
calculated first, so the two benefits stack. Nature levels 0 through 2 are
unchanged. VV3's shared aging loop applies the shift during normal play and
elapsed-time catch-up.

VV5 HEATHEN MOMMY PUZZLE RESTORATION

The naturally enabled reference creates a 29th, tag-17 Heathen mother and gives

The full visible tile shows "This milestone has not been completed!" while

The pair uses two physical population slots. Existing saves are not

VV5 EASIER DEVOTEE TRAINING

Any villager with positive Devotion skill can spontaneously choose the game's

VV5 STATUE DROPS: NORMAL ACTION OR HONORING

NUMERIC KEYS ZIP AROUND THE ISLAND (A NEW HOME)

The later games let the number keys jump the view to one of nine sections of
the island, laid out like a numeric keypad:

    7 8 9    top row
    4 5 6    middle
    1 2 3    bottom row

A New Home now does the same, and glides there the way The Lost Children does
rather than jumping. Both the top-row digits and the numeric keypad work.
Holding a key does not repeat; scrolling by hand while it is gliding cancels
the glide; Ctrl+digit and Alt+digit are left alone; nothing happens until a
village is on screen. It also adds the loading-screen tip "You can zip around
the island with your numeric keys."

The feature is its own companion, VVFP VV1 Number Keys.dll, which the Origins
companion loads once per game session. So the row runs on the
Origins-exclusive base, which the patcher installs automatically with it:
there is no separate box to tick, and selecting this row also adds the
Origins Upgrades buttons to the Tech and Villager Details screens. No
executable space is claimed for the tip: its text replaces the unused
demo-version message.

The Lost Children's matching tip is reworded from "keypad" to "numeric keys"
by its own small row, Tip Wording: Numeric Keys.

SHOW PARENTS IN DETAILS SCREEN (A NEW HOME)

The Lost Children and the later games remember each villager's mother and
father for life and show them as two small figures in the Details portrait
while the villager is a child. A New Home keeps nothing of the kind, so this
row adds it.

While a villager is under 18 -- and again if they are ever made younger --
two small, half-faded figures of the parents stand in the upper corners of
the Details portrait: the father on the left facing right, the mother on
the right facing left, each drawn from that parent's own head and body.
Rest the mouse on one and "Son of <name>" or "Daughter of <name>" appears
under the portrait. Nothing is shown for a villager whose parents are not
recorded: founders, and anyone born before the row was on.

How it is recorded. At conception the father's name, head and body are set
aside against the mother (this is the same moment the parentage log's hook
fires, and it is that hook that supplies him, so with Write Births and
Conceptions Log to Text File unticked only the mother is recorded). At the birth the game's own child-
creation routine hands the named child and its mother to the companion --
so births that happen while the game catches up on time you were away are
recorded just the same -- both parents are written to the child's entry,
the birth is appended to the parentage log at once as a "Birth" record,
and then the entry is saved to "Virtual Villagers 1 Parentage Records -
Save <slot>.dat" in the "Virtual Villagers Fun Patcher Data\Parentage
Records" folder beside the saves.
Nothing is written into a villager record or the save.

An entry is never erased. Death leaves it; growing up hides the figures but
keeps the record, so a villager made young again shows their parents again.
Each entry belongs to its villager, not to a record slot: when the game
loads a save it renumbers the villagers (everyone after a villager who died
moves down), and the entries move with them, matched by name, gender and
family. A new villager starts with no parents, and two villagers who share
all three are left without parents after a renumbering rather than guessed.

The Village Population roster shows the same record as a "Parents:" block
on each A New Home villager whose parents are known.

The feature is its own companion, VVFP VV1 Parentage.dll, which the Origins
companion loads once per game session. So the row runs on the
Origins-exclusive base, which the patcher installs automatically with it:
there is no separate box to tick, and selecting this row also adds the
Origins Upgrades buttons to the Tech and Villager Details screens.

MOVE THE "PLAYING IN THE DIRT" SPOT (NEW BELIEVERS)

In the stock game a child who plays in the dirt walks to a strip of ground
that runs from the rainbow totem's side down across the river, so the child
wanders through the water and ends up on the bank behind the research
shelves. This patch makes it the flower patch east of the dirt path (the
worn ground with the flowers, west of the flower rock; about 305 by 205, and
the child takes six random steps inside it). The game's own routine is
recoded in its own bytes (no space is added);
the action, its text, its sound and its length are as before. Nothing is
saved: it is purely where the child walks.

DEVOTED SOUL EPITAPH (NEW BELIEVERS)

When a villager is buried, New Believers writes an epitaph on the grave
from their job (the grave's job is their highest skill). Every job already
gets one of two epitaphs on a coin flip, except the Devotee, who was always
"Respected Citizen". With this patch a buried Devotee gets "Respected
Citizen" or "Devoted Soul" with equal chances. Nobody else changes: an adult
with no skill keeps "Respected Citizen", and children, villagers with three
or more master skills and every other job keep their own epitaphs. The
epitaph is kept in the grave like any other, so it is saved, you can still
edit it, and the Deaths log records it.

SORT BY AGE/SKILL/HEALTH IN DETAILS SCREEN (A NEW HOME)

The Lost Children and the later games let you sort the villagers you step
through with the Details arrows. A New Home gets the same band, under the
Age and Gender boxes: "Sort By:" with Age, Skill and Health, each with a
radio. Click a plate or its radio to choose the order; Age is the default.

The orders are the later games', measured in The Secret City: each one is
ascending -- youngest first, lowest highest-skill first, lowest health
first -- with earlier villagers first among equals, wrapping at either end.
One quirk is kept on purpose because the later games have it: the place in
the list is kept when you change the order, so the next arrow press shows
the villager at the next place of the NEW order. Choosing a villager any
other way (the strip, the village) starts the arrows from that villager.

Nothing is saved: the order lasts for the session, as in the later games.
The feature is its own companion, VVFP VV1 Sort By.dll, which the Origins
companion loads once per game session. So the row runs on the
Origins-exclusive base, which the patcher installs automatically with it:
there is no separate box to tick, and selecting this row also adds the
Origins Upgrades buttons to the Tech and Villager Details screens.

THE PATCHER'S OWN FILES, AND HOW TO CLEAR THEM

Everything this patcher writes for a village sits beside that village's save,
in Documents\LDW\<game folder>\ -- the same folder as the .ldw files -- or in
its "Virtual Villagers Fun Patcher Data" and "Virtual Villagers Fun Patcher
Logs" subfolders.

Each kind of data file has a folder of its own inside "Virtual Villagers
Fun Patcher Data", one file per save slot:

    Village Masks\                                 (Origins masks)
        Virtual Villagers 1 Village Masks - Save <slot>.dat     A New Home
        Virtual Villagers 2 Village Masks - Save <slot>.dat     The Lost Children
        Village Masks - Save <slot>.dat                         The Secret City,
                                                                The Tree of Life,
                                                                New Believers

    Parentage Records\                             (Show Parents in Details Screen)
        Virtual Villagers 1 Parentage Records - Save <slot>.dat     A New Home

    Graves\                                        (Cause of Death)
        Virtual Villagers 1 Graves - Save <slot>.dat     A New Home
        Virtual Villagers 2 Graves - Save <slot>.dat     The Lost Children

    Unaccounted Villagers\                         (Cause of Death: the village
        Virtual Villagers <N> Village Roster - Save <slot>.dat  as it was at
                                                    each save, all five games)

    Village Statistics\, Stew Discoveries\, Village Elders\  (Village Statistics)
    Custom Titles\                                 (Story / Cheat Upgrades)

(The Unaccounted Villagers roster is not the "Village Roster - Save <slot>.dat"
in Village Statistics\: that one is the statistics' own, and a different file.)

MOVED FROM AN OLDER BUILD. Builds before v1.35.58 wrote the masks, parentage
records, graves and Unaccounted Villagers roster loose in "Virtual Villagers
Fun Patcher Data" itself. The first time this build needs one of those files
it moves it into its folder; it never moves one over a file already there --
if both exist, the one in the folder is used and the loose one is left exactly
as it was -- and if a file cannot be moved (another program has it open, say)
it is used where it is and the move is tried again next time. Nothing is
copied, overwritten or deleted on the way. (Still older builds wrote
vv1_masks_<slot>.dat, vv2_masks_<slot>.dat, vvfp_masks_<slot>.dat and
vv1_parents_<slot>.dat directly beside the saves; this build moves such a file
straight into its folder the same way.)

Retired -- written by older builds of A New Home only, never by this one, and
removed by this one once the save has taken over (see below). It stays where
the older build left it, in "Virtual Villagers Fun Patcher Data" (or, older
still, beside the saves):

    Virtual Villagers 1 Origins Doublers - Save <slot>.dat   (vv1_doublers_<slot>.dat)

Exported logs:

    Virtual Villagers Fun Patcher Logs\Births and Conceptions\
        Virtual Villagers <N> Births and Conceptions Log <n>.txt
    Village Statistics - Save <slot>.txt
    Village Population <slot>.txt

DELETING ANY OF THESE IS SAFE. None of them is the game's save, and none is
required for the game to run. Every mask file is read by code that clears its
table first and treats a missing file as "this village has no masks", so
nothing crashes and the file is written again the next time you choose one.
The parents file is read the same way, but what it records cannot be rebuilt:
delete it and every villager in that village becomes a villager of unknown
parents, until the next births fill it in again.
The statistics and population logs are rewritten in full on every save, so a
deleted one simply reappears, complete and up to date, after you next save.

Two of them are worth knowing about before you delete them.

The Births and Conceptions log is built up over time, one record per
conception and one per birth (in A New Home the Birth records need Show
Parents in Details Screen), so deleting it does not lose the feature -- the
file is recreated with a fresh village header at the next save when Write
Village Statistics to Text File is on, or with its next record, unlabelled,
when it is off -- but the older records in it are not recoverable. Keep a
copy if you want that history.

The same log also gets an "Arrived" record for every villager who joins the
village without being born into it -- a new village's founders ("How:
Founder"), an island event's newcomers (the event's name), the Barrel of
Babies, the Custom Island Event's new villagers -- when the Cause of Death
patch is on. Villagers already in a village who arrived before v1.35.58 are
offered an Arrived record once, by the Repair / Not now question shown when
the village is loaded; that it has been done is kept in
"Virtual Villagers Fun Patcher Data\Arrivals\Virtual Villagers <N> Arrivals
Recorded - Save <slot>.dat" (deleting it only means the question can come
back; Start Over deletes it).

The A New Home doubler file is retired. Older builds wrote it to record which
Origins tech and food point doublers a village had bought, because the save did
not keep them. The save keeps them now, and this build never writes the file.

If one is still there from an older build, it is read once. The first time a
village is loaded on this build, any doubler the file records for that village
is carried over and kept in the save from its next save on. Once a save with
that record is on disk, the next load deletes the file. Nothing else is ever
deleted: only the patcher's own file for that slot, only after it has been
opened and checked to be one, and never a game save or anything else in the
folder. Start Over removes it as well.

So a doubler bought under an older build is safe as long as the file is still
there the first time that village is loaded on this build. Deleting it yourself
before then means buying those doublers again; at any other time it costs
nothing. Either way it cannot crash anything or harm the save. A file left
behind by a different village in a reused slot is ignored rather than applied,
and is removed the same way.

WHEN TO USE THIS. If masks ever appear on villagers you did not give them to,
delete the mask file for that save slot. Close the game, delete that slot's
mask file, and start the game again -- the new village begins with no masks.

New Believers and The Lost Children no longer need this. Their mask files
now record the living villagers of the village that wrote them, and the game
notices when the village changes, so a new village started in a reused slot --
whether through Start Over or by deleting the tribe -- begins with no masks on
its own.

One thing to expect: the very first load after updating shows no masks even
on a village that had them, because the older file carries no village record
and is ignored rather than trusted. Choose them again and they stick. Villagers
being born or dying does not count as a new village, so ordinary play never
clears anyone's masks.

(v1.35.13 did not save New Believers' masks at all: its file was bound to a
village identity read from the wrong place, so it was never written. This
build writes it; choose the masks once more and they persist from then on.)
